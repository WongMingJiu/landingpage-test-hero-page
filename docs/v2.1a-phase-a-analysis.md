## 1. V1 pipeline understanding

入口 `run.sh`，五段式：

| 步骤 | 动作 | 关键参数 |
|---|---|---|
| 1 | ffmpeg 截帧 | **1 fps，0–29s 共 30 帧** → `output/{name}/video_clip_result/frame_XX.jpg`（帧号 = 秒数） |
| 2 | 提取音频/视频片段 | 前 30s，16kHz 单声道 wav；另有 30s mp4 clip |
| 3 | Whisper 本地转写 | `transcribe.py`，模型默认 `small`；**只写扁平 `transcript.txt`，丢弃时间戳**；空转写直接 `exit 5` 中止 |
| 4 | 多模态分析 | `analyze.py`：OpenAI 兼容 `/v1/chat/completions`，帧以 base64 data-URL 注入，每帧压到 ≤100KB（长边 ≤1280）；默认 `FRAME_SAMPLE_STEP=3` + `MAX_API_TOTAL=10`（含老师三视图参考图 2 张）→ 实际发给模型的帧很少且偏向头部采样；`temperature=0.3`、`max_tokens=16384`、3 次指数退避重试；帧附带 “frame_XX（第 X 秒）” 文字标注 |
| 5 | 方案生成 | `generate.py` → 在 `analysis.json` 之上产出 10 套落地页方案 + `design_refer/` |

V1 与 V2.1a 的三个本质差距：

1. V1 转写**无时间戳**；V2.1a 需要 timestamped transcript（Spec §4.1 输入合同 + evidence `time` 字段）。
2. V1 帧采样（步长 3 + 头部截断）**稀疏且偏前段**，后段覆盖缺失；V2.1a 的 Opening 判定要求 0–10s 高密度。
3. V1 空转写即中止；V2.1a 明确 `transcript_sparse != semantic_sparse`，稀疏转写是正常态，不得中止、不得触发扩窗。

## 4. Exact data flow

```text
video.mp4
 │
 ├─ extract.py（V2 自己的 working dir，不写 V1 目录；若 V1 帧已存在可只读复用）
 │    ffmpeg 1fps → v2/work/frames/frame_00..29.jpg        （0–29s，30 帧）
 │    ffmpeg -t 30 → v2/work/audio_0_30.wav                 （16k mono）
 │    whisper segments → v2/work/transcript_0_30.json       （[{start,end,text}]；空也合法）
 │
 ├─ frames.py：选出发送帧集合（默认 20 帧，见 §5）
 │
 ├─ tagging.py 阶段 1：
 │    system = creative_tagging.md（内嵌渲染后的三套 taxonomy 全文）
 │    user   = 20 帧（逐帧“第 X 秒”标注）+ 带时间戳转写段 + 画面文字提示
 │    → 模型返回完整 creative_tagging_v1 JSON（含 semantic_sufficiency）
 │
 ├─ schema.py 校验：结构 / 枚举 / 标签 membership / Active 约束
 │
 ├─ 分支：
 │    sufficient → 直接定稿：used_seconds=30, extended=false
 │    insufficient → extract 30–59s 帧 + audio_30_60 + segments
 │         → 阶段 2（extension.md：阶段1草稿 + 30–60s 证据 + §5.4“只澄清不篡位”）
 │         → used_seconds=60, extended=true, extended_reason 必填
 │         → 仍不足：review.needed=true, reason="insufficient_multimodal_evidence"
 │
 └─ 写 output/{video_name}/v2/creative_tags.json
```

`creative_id`：CLI `--creative-id` 显式传入，缺省 = 视频文件名（去扩展名）。

V1 `analysis.json` 按 Spec §4.2 为可选辅助输入：默认**不注入**（避免结构化推理污染证据优先级），仅 `--use-v1-analysis` 开关启用，且 prompt 中声明其不得作为唯一依据。

## 5. Exact multimodal / frame sampling strategy

**原始抽帧层：保留 V1 同款 1 fps。** V2 自行执行（与 `run.sh` 相同 ffmpeg 参数），0–29s 共 30 帧。不引入任何新视觉框架、不做镜头切分/场景检测——最小可靠。

**发送给模型的帧（默认预算 20 帧）：**

| 区间 | 采样 | 帧秒数 | 数量 |
|---|---|---|---|
| 0–10s（Opening 区） | **1fps 全保留，永不降采样** | 0,1,2,...,10 | 11 |
| 10–30s（主窗口余段） | 每 2s 一帧 | 12,14,16,18,20,22,24,26,28 | 9 |

**设计论证：**

- **0–10s Opening 不丢的保证（C1 硬约束）**：帧选择器以代码硬约束“0–10s 区间恒 1fps 全保留”，配 unit test。**任何情况下 0–10s 不得降采样**——若单次请求容不下完整帧集，走分批/分阶段请求（见下条），而非牺牲 Opening 密度。
- **充分性论证（对照 Seed Benchmark 全部 10 条的证据时间轴）**：所有样本的决定性开场证据起点均 ≤12.5s，且最密集区在 0–10s（v01: 0–2.5s；v08: 0s；v10: 0–12.5s 持续横幅）——11 帧 1fps 全覆盖；后段所有证据段（12.5–20s、17.5–25s、22.5–27.5s 等）跨度均 ≥2.5s，2s 间隔保证每段 ≥2 帧落入。
- **字幕/横幅/标题卡**：VLM 直接从帧读取画面文字（V1 同款做法），不引入 OCR；0–2.5s 的开场横幅由 frame_00–02 保证。
- **动作示范**：1fps/2fps 相邻帧间推断动作连续性；教学动作（如“抬眉瞪眼闭嘴吸气”）在 benchmark 中均为持续画面（≥5s 跨度），采样密度足够。
- **人物关系（老师/学员/家人）**：横幅文字（“只跟宋伶俐学了一个月”“妈妈报了训练营”）+ 画面人物组合判断，不依赖人脸匹配。
- **演唱**：视觉证据（持麦、对麦演唱、琴前教唱）记为 `visual`；Whisper 输出的歌词/空白模式记为 `transcript`；**不得**因“推断在唱”而标 `audio`（MVP 无音频理解组件，详见 §7/§8 source 归属规则）。prompt 明确告知“转写空缺可能对应演唱段而非无内容”。
- **观众反应**：反应镜头（鼓掌、“好听”）位于 12.5–20s 类区段，2s 间隔覆盖。
- **模型/API 图片数量限制**：仓库内无硬性文档上限；V1 的 `MAX_API_TOTAL=10` 是含老师参考图的自设保守值。V2 不注入参考图，预算全部给帧：20 帧 × ≤100KB ≈ 2MB（base64 后 ≈2.7MB）请求体，与 V1 同一网关包络。以 `V2_FRAME_BUDGET` 环境变量可调；Phase B 首条视频 smoke 时实证确认网关实际上限。
- **预算不足时绝不牺牲 Opening 覆盖（C1 硬约束，分批/分阶段策略）**：若单次多模态请求无法容纳完整帧集，按以下优先级处理，**0–10s 1fps 全 11 帧永不裁剪**：
  - 方案 A（首选，单请求）：完整 20 帧一次发送。
  - 方案 B（单请求超限）：拆为同会话两次请求——请求 1 发 0–10s 全部 11 帧（Opening 优先完整送达），请求 2 发 10–30s 的 9 帧，第二次请求携带第一次的初步结论作为上下文，最终由 `tagging.py` 合并定稿。
  - 方案 C（单请求上限极低，连 11 帧都超）：Opening 11 帧仍单独成一次请求保完整，后段按 2s 间隔分多批补齐并合并。
  - 任何分批方案都保留 0–10s 全部 11 帧进入模型；分批合并逻辑由 `tagging.py` 编排，对最终 JSON 透明（模型仍按完整证据集作答，不感知分批）。
- **扩窗时（仅 30–60s）**：1fps 抽 30–59s，发送每 3s 一帧（30,33,...,57 共 10 帧），同样可调；若该帧集也超单请求上限，同样走分批策略，Opening 区（0–10s）依旧不裁。

## 6. Taxonomy loading strategy

三套各一个受版本管理的 JSON（`v2/taxonomy/singing/*.json`），loader 职责：

1. **加载即校验**：Value 必须为 7 个一级类 × 36 标签（与 Spec §3.1 逐字比对）；Opening 18 个标签 + §8.6 优先级全序列；Expectation 15 个标签（含 `无法判断（对于这种情况给一个候选）` 完整字符串）。任何缺失/多余/拼写漂移 → 启动即报错。
2. **完整性强制**：`description` / `examples` / `definition` / `signals` / `boundary_rules` 字段为空 → 加载失败并指明缺哪个标签。**宁可在 BLOCKER 解除前无法运行，也不允许裸枚举进 prompt**（Spec §3.1/§3.2/§3.3 的强制要求）。
3. **渲染入 prompt**：按“标签 + 原表描述 + 识别示例 + 边界规则”结构化渲染；Spec §7 的 8 组 Value 边界规则、§8.1–8.6 Opening 规则、§9.1 Expectation 边界作为 **spec 来源字段**并入对应标签/章节（这些在 Spec 中已有，不属于补写）。
4. **输出 membership 校验**：模型输出的所有 `label`/`category` 必须精确命中 taxonomy 字符串，否则拒绝该输出并触发重试。

数据结构（示意）：

```text
value.json:
  { taxonomy_id, source,
    categories:[{ category, active_limit,
                  labels:[{ label, description, examples[], boundary_rules[] }] }] }

opening.json:
  { labels:[{ label, priority, definition, script_signals[], visual_signals[], rules[] }],
    decision_priority[], unit_rules(§8.1–8.5) }

user_expectation.json:
  { labels:[{ label, definition, signals[], exclusion_rules[] }],
    boundary_rules(§9.1) }
```

Active 上限（演唱能力 3 / 心理障碍突破 2 / 学习降阻 2 / 专业认知提升 2 / 社交价值 1 / 信任保障 1 / 课程权益 2）来自 Spec §6.4，编码于 `value.json` meta，由 `schema.py` 强制执行。

## 7. Prompt strategy

**主 prompt（`creative_tagging.md`，中文）**，内容全部来自 Spec，无自创规则：

- 角色与任务边界：只做三类标签，不做 Primary Driver / Hero / 生图（§1.2）；
- 证据优先级公理：`Raw multimodal evidence > existing structured inference > model common-sense completion`；素材未表达的不补标（§4.3）；
- Decision Window：0–30s 为主窗口；`transcript_sparse != semantic_sparse` 原文写入；扩窗仅当三类输出无法稳定判断（§5）；
- 三套 taxonomy 全文块（由 §6 loader 渲染）；
- Value 规则：strong/medium 门槛、weak 禁止、不允许打标四情形、Salience 四条参考、Active 数量全局与分类上限、Precision > Recall（§6）；
- Opening 决策：识别单元、多分镜规则、脚本多标签映射、分镜覆盖、三种 fallback 与 source_mode、优先级表，以及“优先级只用于同一开头单元内多候选决胜，不允许后段覆盖前段”（§8）；
- Expectation 决策：唯一标签、无法判断 + candidate 形态、§9.1 边界、与 Opening 独立判断（禁止机械映射，引用 benchmark §4.2 的三个反例口径：v03 / v05 / v07）；
- Evidence 规范：每条正式标签 ≥1 条 `{time, source∈subtitle|audio|visual|transcript, content}`；confidence 只用 high|medium|low，禁止伪精确数字（§10）。
- **Evidence source 必须反映系统实际观察（C2 硬约束）**：
  - `visual` = 模型从画面帧直接观察到的事实（含“看到持麦演唱”这类视觉推断）；
  - `transcript` = Whisper 转写文本（含歌词、口播、空白/稀疏模式）；
  - `subtitle` = 画面内字幕/横幅/标题卡文字（由 VLM 从帧读取，Spec 单列以便溯源）；
  - `audio` = **仅当存在真实的音频理解组件分析了该证据时**才合法。MVP 仅投喂帧 + Whisper 转写，**无音频理解组件**，因此 MVP 阶段 `source="audio"` 一律非法——模型不得基于“推断某人在唱/在说”而标 `audio`，这类推断必须记为 `visual`（视觉推断）或 `transcript`（转写内容）。
  - Prompt 必须显式告知模型上述归属规则，并禁止在无音频组件时产出 `audio` 证据。
- 输出契约：`creative_tagging_v1` JSON 逐字段骨架（§11 原样）；
- 不足处理：`semantic_sufficiency=insufficient` 的判定口径 + 禁止为凑 JSON 硬猜（§12）。

**用户消息**：20 帧逐帧标注“第 X 秒”；带时间戳转写段 `[start–end] text`（含空转写提示：空缺可能为演唱段）；明确“注意画面字幕/横幅/标题卡文字”。

**扩窗 prompt（`extension.md`）**：携带阶段 1 草稿 + 30–60s 帧与转写；写入 §5.4 四允许（补缺失语义、解释前段、消歧、闭环命题）与“不得推翻前 30 秒已充分成立的判断”。

**调用参数**：`temperature=0`（Spec §13.6 稳定性要求；V1 的 0.3 不适用于需要三次运行不漂移的场景），`max_tokens=16384`，3 次重试退避——与 V1 同一客户端模式。

## 8. Exact Schema implementation strategy

**第一版逐字冻结 `creative_tagging_v1`，零改动。** `schema.py` 手写校验（不引入 jsonschema 依赖）：

| 字段 | 契约 |
|---|---|
| `schema_version` | 字面量 `"creative_tagging_v1"` |
| `creative_id` | string，非空 |
| `decision_window` | `primary_seconds` 恒 30；`used_seconds ∈ {30,60}`；`extended` bool；`extended_reason` 与 extended 一致（true 时非空）；`semantic_sufficiency ∈ {sufficient, insufficient}` |
| `matched_value_tags[]` | `category`/`label` ∈ taxonomy；`evidence_strength ∈ {strong, medium}`（weak 出现即拒绝）；`salience ∈ {primary, supporting}`；`evidence[]` 非空，`source ∈ {subtitle, audio, visual, transcript}` |
| `active_value_tags[]` | 纯 label 字符串；⊆ matched labels；总数 ≤5；其中 primary salience 1–2 个、supporting 0–3 个；分类上限按 §6.4 表 |
| `opening_type` | label ∈ 18 枚举；`source_mode ∈ {script_and_visual, visual_only, script_only}`；confidence 枚举；evidence ≥1 |
| `user_expectation` | label ∈ 15 枚举；`无法判断（...）` 时 `candidate` 必填且 ∈ 其余 14 枚举；其余情况 candidate 必须为 null；evidence ≥1 |
| `review` | `needed` bool；`reason` 一致（不足时为 `insufficient_multimodal_evidence`） |

校验失败 → 携带错误清单重试模型（≤3 次），仍失败则落盘原始返回 + 非零退出（沿用 V1 `analysis_raw.txt` 的排查模式）。
**Evidence source 归属闸（C2 落地）**：`source` 枚举仍为 `{subtitle, audio, visual, transcript}`（Spec §11 冻结，不改枚举）；但 `schema.py` 增加配置位 `V2_AUDIO_UNDERSTANDING_ENABLED`（默认 `false`）：
- `false`（MVP 默认）：任何 `source="audio"` 的 evidence 条目 → 校验失败、拒绝该输出并触发重试；
- `true`（未来接入真实音频理解组件后）：`audio` 证据合法，且须携带该组件的观测来源标记（实现细节在 Phase B 之后另议）。
此闸在代码层强制“证据反映实际观察”，与 §7 prompt 侧规则双重保险。

**Recommendations（仅记录，第一版不实现，不改 Schema）：**

1. `active_value_tags` 用纯字符串导致 salience 需回查 matched，下游消费略绕——未来版本可考虑对象化；
2. evidence 的 `time` 为自由字符串（`"00:00-00:07"`），无机器可解析保证——未来可加结构化起止秒；
3. 输出无 model/时间戳等 provenance 元数据，benchmark 复现追踪靠文件路径约定——未来版本可加 `meta` 块；
4. `source_mode` 枚举是从 §8.5 + §11 示例归纳的三值，Spec 未显式声明枚举集——实现按三值冻结，若业务有第四态需 Spec 先行。

## 9. Semantic Sufficiency / extension implementation

- **判定主体是模型、门槛是代码**：阶段 1 模型必须在 30s 证据上给出完整 JSON + `semantic_sufficiency`；prompt 内原文级强调 `transcript_sparse != semantic_sparse`——ASR 缺失、无口播、演唱段均不构成 insufficient 的合法理由，`extended_reason` 若只谈转写稀疏将被 benchmark 判为窗口逻辑错误（Spec §13.5 + benchmark §4.1）。
- **扩窗只走二阶段**：绝不在首次调用就投喂 0–60s（防“后段篡位”；benchmark §4.4 以 v04 为标准测试题：22.5s 后的稀缺 Offer 不得覆盖前 20s 学员故事主线）。
- **代码侧一致性闸**：`extended=true` 必须同时满足 `semantic_sufficiency=insufficient` 且 `extended_reason` 非空且 `used_seconds=60`；60s 仍不足 → `review.needed=true`。
- **Seed Benchmark 硬断言**：10/10 必须 `used_seconds=30, extended=false`；任何一条扩窗即该维度判错。

## 13. Remaining REAL blockers

**唯一硬 BLOCKER：**

> **`taxonomy_definition_incomplete`** —— 仓库（含未跟踪旧档）中不存在《素材级标签文档（初稿）》原表。Spec 强制要求：
>
> 1. **Value Taxonomy**：36 标签的“标签描述 + 识别示例”缺失（现有：裸标签 + Spec §7 的 8 组部分边界规则）；
> 2. **Opening Taxonomy**：18 类的定义、脚本信号、分镜信号、识别规则缺失（现有：裸标签 + §8.6 优先级 + §8.1–8.5 通用规则；“歌曲带练归教学演示”等具体规则只在 benchmark 判定说明中零散出现，非原表）；
> 3. **User Expectation**：15 标签的“主要识别信号 + 排除/边界规则”缺失（现有：裸标签 + §9.1 的 8 条通用边界）。

按指令：**不自行生成或补写这些业务定义**。解除方式 = 业务方提供原表（建议落为 `docs/taxonomy/` 下文档），实现侧仅做忠实转录。在解除前，§6 的 loader 完整性闸会主动拒绝运行，Phase B 的 taxonomy 数据与正式 prompt 内容无法完成。

**非 blocker 的运行性前提（明确区分）：**

- 10 条本地视频放入 `benchmarks-local/`；
- `config.env` 中可用的多模态 `API_BASE_URL / API_KEY / MODEL_NAME`；
- API 实际图片数量上限（由 `V2_FRAME_BUDGET` 调档，Phase B smoke 实证）。
