## 3. 漂移与本轮改动目标的对应关系

三个漂移边界恰为本轮泛化裁决原则的针对面（注意：以下数据产生于改动前的自由文本笔记管线，见 §5）：

- v04 Opening（学员故事证明型↔剧情/内容叙事型）→ §3.2.2「呈现形式≠说服机制」；
- v09 Opening（低门槛领取型↔权威背书型）→ §3.2.2「辅助信任证据≠开场驱动」；
- v06 Expectation（掌握简单方法↔理解专业原理）→ §4.1「已给动作/跟练→掌握简单方法」；
- v02 Expectation（掌握简单方法↔低门槛开始学习）、v05 Expectation（理解专业原理↔获得/复制演唱效果）→ 结构化证据终审的候选信号 + 相邻区分线索设计目标。

改动方向与漂移根因（自由文本中间层非确定性）一一对应，但**尚无 benchmark 级数据证明漂移被消除**。

## 5. 验收口径说明（重要）

按用户决定，本次以**已完成数据**验收。需要如实记录两点：

1. §2 的稳定性数据与 §4 的准确率数据均产生于**改动前**的自由文本笔记管线（staged 512，temperature=0）。本轮结构化证据 + 受限终审改动在 benchmark 级别**未完成重跑验证**。
2. 未完成的原因：验收窗口内 API 网关持续不稳定。新管线 10×1 重跑（run-id `v2.1a-stab-acc`）中，证据提取调用持续遭遇 `upstream call timeout`，V2_API_RETRIES=5 下单批仍需 3–5 次重试才偶发成功，运行 1 小时以上仅推进 v01 约一半批次，0 个样本完整落盘；冒烟 v01 也需多次重试方走通。此为基础设施可用性问题，非代码缺陷（单测与冒烟均通过）。

## 6. 最终建议

对照本轮验收标准逐条：Window PASS、Primary Core PASS、**Opening FAIL**（2 个样本漂移到未文档化备选）、**Expectation FAIL**（7/10 < 9/10）。且本轮稳定性改动本身缺少 benchmark 级重跑证据。

> ## 建议：**DO NOT PASS**

V2.1a 维持 **Feature Pass / Stability Pending**。

剩余验收动作（不涉及 V2.1b，均为本轮改动的验证收尾）：

1. 待 API 网关恢复稳定后，用当前代码（结构化证据 + 受限终审）重跑 10×1 确认准确率不低于 §4 门槛；
