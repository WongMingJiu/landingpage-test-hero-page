## 4. 失败归因（关键结论）

1. **不是实现漂移**：固定证据 replay 下 Opening 稳定且正确率可达 9/10；失败集中在 Expectation 语义判断与 primary salience 取舍，且错误全部落在已知难边界（v02 掌握简单方法 vs 低门槛、v05 理解专业原理 vs 复制演唱效果、v09 低门槛 vs 权威背书）。
2. **是可用模型的能力上限**：原验收（gpt-5.4）曾达 Opening 9 / Expectation 9 / Core 9；当前可达的任何 provider 模型在 Expectation 上最高仅 6/10。这些边界正是 gpt-5.4 与较弱模型的语义能力差距所在。
3. **基础设施改造完全达标**：provider 适配器零产品改动换端点；证据工件 + replay 在网关不可用期间完成了全部稳定性诊断与模型对比（本次 m3 跑批的 v01/v04 失败样本也靠 replay 工件直接补齐，无需重跑视频）。

## 5. 仍需活跃（且足够强的）多模态 provider 才能完成的验证

1. Expectation ≥9/10 的复现（需要 gpt-5.4 级别的语义模型；原网关 key 失效，需恢复凭据或接入等价模型）。
2. 达标后的 10×3 E2E 稳定性终门（Window 30/30、Opening 稳定、Expectation ≥9/10 样本稳定、Core 每轮 ≥8/10 无 wrong/exact 振荡）。

## 6. 最终建议

**DO NOT PASS**（V2.1a 维持 Feature Pass / Stability Pending）

- 阻塞项已完全定性为**provider 能力/可用性**，而非产品实现：Window/Opening/Core/Evidence 四门槛在可用模型上已通过或达标；Expectation 差距与已知难边界一一对应。
- 行动项：① 恢复 `llm.gw.dachensky.com` 凭据或接入语义能力 ≥ gpt-5.4 的多模态模型；② 用该模型重跑 10×1（可复用现有 10 份证据工件做 replay 预审）；③ 达标后跑 10×3 终门。**无需任何产品/决策层改动。**
