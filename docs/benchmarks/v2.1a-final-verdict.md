- 结论：**8-video validation 有诊断价值，但不能证明 canonical 10-video Strict Final Pass。**

8 个冻结工件 ×3 轮 adjudication-only replay（qwen3.8-max @ cf.api.fan）：

- 无 exact↔wrong 振荡

**结论：在冻结证据上，终审裁决是确定性函数。决策稳定性维度关闭。**

## 3. 证据提取稳定性（结构确认）

qwen3.7-plus 轮（v02/v04/v05/v06/v09 ×3）与 qwen3.8-max 轮（v02/v04/v05/v06 ×3）：

- 字符串层不可复现（temperature=0 下跨轮精确重叠 Jaccard ≈0.00–0.43）
- 观测条数与语义内容稳定（同一屏幕事实/字幕/候选主题每轮复现）
- qwen3.8-max 字符串级可复现性高于 qwen3.7-plus（Jaccard 0.13–0.43 vs ≈0.00），但均非精确确定
- 未出现需要升级为 30× 全量 E2E 的系统性偏差

**结论：裁决稳定性必须基于冻结工件 replay 测量；重新生成工件不能替代 replay。**

## 4. 剩余准确率问题的归因（修正表述）

现有实验**没有严格隔离变量**。Evidence Extraction 的最终质量是
**Provider × Extraction Harness 共同作用的结果**，其中 Harness 包括但不限于：
抽帧策略、staged 分批方式、Evidence Extraction Prompt、observation schema、
candidate signal 提取方式、merge / normalization 方式。

**准确结论**：当前剩余准确率问题主要集中在 Evidence Extraction 层，并且对模型 Provider
存在明显敏感性；现有数据**不足以**进一步区分是 Provider 语义能力、Extraction Prompt
还是 Harness 适配造成的具体贡献。

（此前报告中"accuracy is provider-bound, not implementation-bound / 纯 Provider 问题"
的表述属于过度归因，已删除。）

同理，不对模型做全局能力排名：
- 当前数据只支持——在现有冻结证据与当前 GT 下，qwen3.8-max 在 **User Expectation 细粒度裁决**
  上的表现优于目前观察到的 qwen3.7-plus 结果；
- 但 qwen3.8-max replay Opening 为 7/10，而 qwen3.7-plus 完整 E2E 曾达 Opening 10/10，
  因此**不能**推导 qwen3.8-max 在所有 Creative Tagging 决策维度上更强；
- 也**不应**将 qwen3.7-plus 描述为"弱模型"或"语义能力达到天花板"——10 条 Seed Benchmark
  样本太小，且多个 User Expectation case 本身属于相邻语义边界，不足以做模型总体能力排名。

## 5. Known Limitations（已知边界限制）

### A. User Expectation 相邻语义边界
以下标签在部分素材中存在天然连续关系，Seed Benchmark 中也出现了人工判断边界：
获得/复制演唱效果、掌握简单方法、理解专业原理、复制学员成功路径。
因此 User Expectation exact-match **不应被解释为模型整体素材理解能力**。

### B. Evidence Extraction 对 Provider 敏感
不同 Provider 在相同素材上的 Evidence Extraction 质量存在差异。这是真实工程风险，
但当前证据**不能**进一步断言具体原因来自：模型能力 / Prompt 适配 / Harness 设计 /
多模态输入处理 中的哪一项。

### C. Seed Benchmark 样本规模有限
当前仅 10 条素材。适合作为：回归测试、产品规则验证、早期能力 Gate；
**不足以**作为不同大模型总体能力排名的可靠依据。

## 7. V2.1b 状态

**V2.1b 可以正式开始。**

### V2.1b 上游输入契约（正式）

- **V2.1b 的必需输入只有 `creative_tags.json`**，包含：matched_value_tags、
  active_value_tags、opening_type、user_expectation、evidence、confidence、
  decision_window / review 等 creative_tagging_v1 现有字段。
- **`structured_evidence.json` 不属于 V2.1b 必需输入**，也不属于 V2.1a 正式输出。
  它是 staged 路径的中间工件，定位为 Benchmark / Debug / 稳定性分析 / 异常排查工具；
  未来调试或研究可以额外读取，但**不得形成正式业务依赖**。

V2.1a 正式输入：广告视频。V2.1a 正式输出：creative_tags.json。
正式生产链路：广告视频 → 0–30s 多模态理解 → 直接完成 Creative Tagging →
creative_tags.json → V2.1b Intent Decision。

V2.1b **不应**把 User Expectation 单一标签作为唯一决策依据，而应综合
creative_tags.json 内的：matched / active value tags、Opening Type、User Expectation、
evidence（关键原始证据）与 confidence，进一步判断：
- Primary Driver
- Unresolved Question
- Intent Strength
- 后续 Hero 承接方向
