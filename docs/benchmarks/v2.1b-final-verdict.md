## 5. 失败样本分析（v07 / v08）

### 5.1 v07 — 窄化型 mismatch：substantive semantic miss（轻度）+ judge 边界因素

**Actual Q**："这个简单的手部动作具体怎么练才能让我唱得和她一样好听？"
**GT Q**："她到底学了什么、怎么练，才会在这个年龄唱出这样的效果，我跟着学也能做到吗？"

归因分析：

1. **实质偏差（主体）**：模型把 GT 的复合信息缺口（学了什么 + 怎么练 + 我能否复制）窄化为单一子项（"手部动作怎么练"）。V2.1a evidence 中"画面中女性演示手部动作"表明动作本身已被展示——模型选择了已部分回答的子缺口，而非真正未回答的完整学习方法体系。
2. **Judge 边界因素（次要）**：上一轮 intent-b1 中几乎同向的输出（"这个简单动作具体怎么练才能让我唱出同样好听的效果？"）被同一 judge 判为 match；本轮 GT 换为完整版后判为 mismatch。这说明该样本处于 judge 判定边界附近——方向正确但完整性不足的输出，其 pass/fail 对 GT 措辞与 judge 非确定性敏感。
3. **分类结论**：substantive semantic miss（轻度窄化），叠加 judge ambiguity。不是 acceptable variation（缺口指向确有实质差异），也不是 judge failure（judge 输出合法且理由与 evidence 一致）。

### 5.2 v08 — 偏移型 mismatch：substantive semantic miss（跨轮稳定）

**Actual Q**："这个简单的呼吸方法具体如何运用到完整歌曲中，以及我是否真的能像视频中的老人一样唱好？"
**GT Q**："这个简单方法具体该怎么做、怎么练，才能真的改善我唱歌时喉咙用力的问题？"

归因分析：

1. **实质偏差**：GT 的缺口是"技术落地"（这个方法具体怎么练、怎么改善喉咙用力），模型的缺口是"效果验证 + 迁移"（能否用到完整歌曲、能否像老人一样唱好）。方向相关（都围绕简单方法之后怎么办），但信息缺口指向实质不同。
2. **跨轮稳定**：intent-b1 与 intent-b2 两轮独立运行中，v08 的输出几乎逐字一致且均判 FAIL——这不是随机波动，而是模型在该样本上的稳定行为边界：倾向于把 Unresolved Question 放在"效果确认"框架，而非"操作落地"框架。
3. **分类结论**：substantive semantic miss（稳定）。不是 acceptable variation（缺口指向不同），不是 judge failure（两轮判定一致且理由清晰）。

### 5.3 严重程度综合判断

两个 mismatch 均**不是方向性大错**：没有凭空创造新痛点（Rule 8 违反）、没有重复广告已明确回答的问题（如年龄能不能学）、没有脱离 Primary Driver 的问题。它们是同一类能力边界的两种表现——**在"信息缺口的具体指向"上与人工 GT 存在分歧**（窄化 / 偏移）。

Question Gate 恰好 8/10 达标。结合上述严重程度：两个失败均有实质语义依据（非 judge 误判主导），但不构成对 V2.1b 核心职责（收敛唯一 Primary Driver + 真正 Unresolved Question + 可追溯 Evidence）的否定。Primary Driver 10/10 说明"核心点击因果链收敛"这一最难的部分全部正确。

## 6. 已知边界限制（Known Boundary Limitations）

1. **v08 型偏移（稳定）**：当广告同时呈现"极简方法演示 + 同龄人效果"时，模型倾向把 Unresolved Question 放在效果验证/迁移（"我能不能唱好"），而非 GT 预期的操作落地（"具体怎么练"）。
2. **v07 型窄化（边界）**：当 GT 的问题是复合信息缺口时，模型可能收敛到其中单一子项，且该类样本的 judge 判定处于边界（对 GT 措辞与非确定性敏感）。
3. **Intent Strength 观察项 9/10**：v02 判 strong（GT medium）。GT 判 medium 的依据"教学与效果均较强存在竞争 Driver"属于较细粒度的人工判断，模型判 strong 为可解释边界。
4. **LLM judge 单次判定的非确定性**：judge 与被测同 provider（qwen3.8-max），边界样本（如 v07）在不同 GT 措辞版本下判定可翻转。本轮已通过"严格原生 boolean 校验 + 失败重试 + judge_failed 显式记录"消除输出格式层面的不可信，但语义判定本身的边界非确定性仍然存在。
5. **网关稳定性（工程环境）**：slb-v1.api.fan 存在连接挂起（本 run v03/v05/v06/v09 单样本耗时 98–280 秒，含 90 秒超时后重试成功；其余样本 7–9 秒）。V2.1b 已用 TimeoutApiClient + 断点续跑缓解，不影响结果正确性，但影响运行时长。

## 8. 最终结论

**B. V2.1b — Accepted with Known Boundary Limitations**
