# V2.1b Intent Decision Spec V1.0

> 状态：Approved for implementation
>
> 所属阶段：V2.1 Creative Understanding / Phase 2
>
> 本文只定义 **V2.1b Intent Decision**。不包含 V2.1a Creative Tagging、Hero Strategy、Hero Copy、生图或线上实验。
>
> 本文为 V2.1b 的正式 Source of Truth，并替代此前 `docs/creative-intent-v1.md` 中关于 V2.1b 正式输入输出的旧设计；旧文档可作为历史设计参考，不作为本阶段实现依据。

---

## 1. 目标

V2.1a 回答：

> **广告讲了什么、怎么吸引用户、让用户产生了什么下一步期待。**

V2.1b 回答：

> **这些信息共同形成了什么核心点击驱动力，以及用户点击后最想继续确认什么。**

业务链路：

```text
广告视频
→ V2.1a Creative Tagging
→ creative_tags.json
→ V2.1b Intent Decision
→ creative_intent.json
→ V2.2 Hero Strategy
```

V2.1b 的职责不是再做一层分类，而是把 V2.1a 的结构化标签与证据收敛成一条完整、可解释、可被下游 Hero Strategy 直接使用的点击因果链。

### 1.1 非目标

V2.1b 不负责：

- 重新读取或理解完整视频；
- 重新执行 V2.1a Creative Tagging；
- 修改 V2.1a Taxonomy；
- 创建新的固定 Driver Taxonomy；
- 直接生成 Hero 标题、副标题或视觉；
- 设计整页模块顺序；
- 为 Seed Benchmark 做特例 hardcode。

## 2. 正式输入契约

V2.1b 的正式必需输入只有：

```text
creative_tags.json
```

不依赖 `structured_evidence.json`。

主要消费字段：

- `active_value_tags`
- `matched_value_tags`
- `opening_type`
- `user_expectation`
- 各标签 / Opening / Expectation 对应的 `evidence`
- `confidence`
- `decision_window`
- `review`

判断时参考优先级：

```text
1. Active Primary Values + Evidence
2. Opening Type + User Expectation
3. Active Supporting Values
4. Matched Values
```

以上只是业务上的参考优先级，不是固定数学权重。

### 2.1 Opening Type 不等于 Primary Driver

```text
Opening Type
= 广告怎么把用户拦下来

Primary Driver
= 什么核心命题让用户觉得值得继续点击
```

例如 `opening_type = 权威背书型` 并不意味着 `Primary Driver = 老师很权威`。

## 3. 正式输出 Schema

Schema Version：

```text
creative_intent_v1
```

推荐结构：

```json
{
  "schema_version": "creative_intent_v1",
  "creative_id": "xxx",
  "primary_driver": {
    "statement": "用户相信……",
    "confidence": "high"
  },
  "unresolved_question": {
    "statement": "这个方法具体怎么做……？",
    "confidence": "high"
  },
  "intent_strength": "strong",
  "supporting_drivers": [
    "老师的专业身份增强了方法可信度。"
  ],
  "evidence": []
}
```

### 3.1 字段约束

#### `primary_driver`

- 必须且只能有一个；
- `statement` 必须是自然语言完整命题；
- 不允许直接使用单一 Value Tag 代替完整 Driver；
- `confidence` 仅允许 `high | medium | low`。

#### `unresolved_question`

- 必须且只能有一个核心问题；
- 必须能够从 Primary Driver 自然推导；
- 不能重复广告已经充分回答的问题；
- 不能凭空创造新痛点；
- `confidence` 仅允许 `high | medium | low`。

#### `intent_strength`

仅允许：

```text
strong | medium | weak
```

#### `supporting_drivers`

- 0–2 个；
- 每个都必须明显增强 Primary Driver；
- 不允许把素材重新完整总结一遍。

#### `evidence`

- 所有 Evidence 必须可回溯到输入 `creative_tags.json` 已存在的 Evidence；
- 不允许创造输入中不存在的时间、事实、人物、动作或话术；
- 实现可设计 `source_ref / source_field / time / content` 等可追溯结构，但不得改变原始证据语义。

## 4. Primary Driver 定义

正式定义：

> **广告已经在用户心中建立的、最能解释其继续点击行为的核心说服命题。**

它不是标签，而是一条完整营销因果链。

错误示例：

```text
Primary Driver = 方法简单易操作
```

正确示例：

```text
原本看起来复杂的正确发声，其实可以通过简单、能跟着做的方法练习，
因此用户觉得自己的发声问题也有机会改善。
```

### 4.1 内部推理框架

模型内部可参考：

```text
Core Need
+
Barrier / Tension
+
Persuasion Mechanism
+
Expected Payoff
```

四项不要求全部存在，也不作为 `creative_intent_v1` 的正式输出字段。

内部角色可包含：

- Core Need：用户最终想解决什么问题 / 获得什么变化；
- Barrier：为什么用户觉得自己做不到 / 不适合 / 难以开始；
- Persuasion Driver：广告为什么让用户开始相信问题有解；
- Trust Driver：为什么相信老师 / 方法 / 课程；
- Offer Driver：为什么现在行动。

这些角色只用于帮助裁决，不要重新变成一套平行 Taxonomy。

### 4.2 Primary Driver 必须唯一

即使素材存在多个强信号，也必须裁决唯一 Primary Driver。

如果真的无法区分主次，应降低：

```text
primary_driver.confidence
intent_strength
```

而不是输出多个 Primary Driver。

---

## 5. Unresolved Question 定义

正式定义：

> **用户点击广告后，广告已经激起但尚未充分回答的最核心问题。**

区分：

```text
Primary Driver
= 为什么我想继续？

Unresolved Question
= 我继续之后最需要确认什么？
```

### 5.1 必须真正 unresolved

如果广告已经明确回答某个问题，则不得重复输出该问题。

例如广告已经明确表达：

```text
94 岁也能学
不限年龄不限基础
```

则不应输出：

```text
我这个年龄到底能不能学？
```

更合理的是：

```text
这个简单方法具体应该怎么练，真的能改善我的发声问题吗？
```

### 5.2 Unresolved Question 不是 User Expectation 的改写

V2.1a `user_expectation` 是标准化分类信号；V2.1b 必须结合完整 Driver 与 Evidence 判断广告到底还留下了什么未解决问题。

---

## 6. Intent Strength

Intent Strength 衡量的是：

> **素材本身是否形成了清晰、集中的点击驱动力。**

不是模型对自己判断的把握程度。

### `strong`

素材信息共同服务于一条清晰核心说服链，没有同量级竞争 Driver。

### `medium`

可以判断 Primary Driver，但存在一个较强的竞争 Driver。

### `weak`

信息分散、不同 Driver 明显竞争，或难以稳定判断主次。

### 6.1 Intent Strength != Confidence

例如：

```text
Primary Driver Confidence = medium
Intent Strength = strong
```

可以表示：素材意图本身很集中，但在“应该如何命名这个核心命题”上仍存在边界判断。

---

## 7. Supporting Driver

正式定义：

> **明显增强 Primary Driver，但不足以单独解释主要点击行为的次级说服因素。**

约束：

```text
0–2 个
```

常见角色包括：

- 专业老师身份增强可信度；
- 学员 / 师生演唱效果提供结果证明；
- 年龄 / 零基础表达降低学习顾虑；
- Offer / 稀缺表达增强当前行动动力。

---

## 8. 核心决策规则

### Rule 1：Presence != Driver

素材里出现某个信息，不代表该信息解释用户点击。

### Rule 2：Opening != Primary Driver

Opening 负责吸引注意，Primary Driver 负责解释用户为什么觉得值得继续了解。

### Rule 3：后段 CTA / Offer 默认不能覆盖前段已成立 Driver

如果前段已经建立清晰 Driver，后段的“领取 / 报名 / 限时 / 稀缺”通常只属于 Supporting / Action Driver。

只有素材主体持续围绕 Offer、资格、权益或稀缺机会展开时，Offer 才可能成为 Primary Driver。

### Rule 4：老师权威默认属于 Trust Evidence

`国家一级演员`、教学经验、媒体背书等通常承担信任作用，不自动升级为 Primary Driver。

### Rule 5：Barrier 可以成为 Primary Driver

当广告主体持续围绕：

```text
你是否适合？
你能不能开始？
```

展开时，解除核心 Barrier 本身可以构成 Primary Driver。

典型样本：v09。

### Rule 6：效果与原理可以共同组成 Driver

不要求把“效果证明”和“机制揭秘”机械二选一。

例如可以形成：

```text
先看到效果
→ 相信这个问题值得继续理解
→ 想知道背后的身体发声机制
```

### Rule 7：禁止 Marketing Imagination

允许：

```text
Evidence
→ 合理的意图推断
```

禁止：

```text
Evidence
→ 创造广告没有表达的营销观点
```

例如素材没有表达“不是天赋问题”，模型不得自行扩写成该认知反转。

### Rule 8：Unresolved Question 必须真正未解决

不能把广告已经回答的问题重新包装成悬念。

### Rule 9：V2.1a Salience != V2.1b Driver Role

V2.1a Primary Value 表示素材显著表达的业务价值；V2.1b 必须判断这些价值在完整点击因果链中分别承担 Need、Barrier、Proof、Trust 或 Offer 作用。

因此 Supporting Value 也可能成为 Primary Driver 命题的重要组成部分。

### Rule 10：Precision > Marketing Completeness

宁可输出较窄但有证据的 Driver，也不要把广告“优化成”一条更完整但素材未表达的营销文案。

## 10. Benchmark 验收标准

首轮 Benchmark 关注语义正确性，不做严格字符串匹配。

### Gate A：Primary Driver Semantic Match

```text
>= 8/10
```

要求核心点击因果与人工 GT 一致，不要求自然语言措辞完全相同。

### Gate B：Unresolved Question Semantic Match

```text
>= 8/10
```

重点检查：

- 是否延续原广告形成的问题；
- 是否真的是广告尚未回答的问题；
- 是否产生无依据的新问题。

### Gate C：Primary Uniqueness

```text
10/10
```

每条素材只能输出一个 Primary Driver。

### Gate D：Evidence Grounding

```text
10/10
```

Driver 与 Question 必须能回溯到 V2.1a Evidence，不允许 Marketing Imagination。

### 10.1 首版观察项

以下首版作为人工质量观察项，不设置严格 Exact Match Gate：

- `intent_strength`
- `supporting_drivers`
- 自然语言表达质量

不要为了 Seed 10/10 自动循环调参。第一次真实运行结果应完整保留，再判断问题来自 Prompt、Schema、模型能力还是 GT 边界。

## 11. 实现约束

推荐独立模块实现，例如：

```text
v2/
  intent_decision.py
  intent_schema.py
  prompts/
    intent_decision.md
```

实际文件结构可根据当前工程组织调整。

正式 Runner：

```text
creative_tags.json
→ V2.1b Intent Decision
→ creative_intent.json
```

推荐正式输出：

```text
output/<creative_id>/v2/creative_intent.json
```

### 11.1 必须满足

- Schema 严格校验；
- JSON 解析失败明确报错；
- 不静默修复业务语义；
- Evidence 引用必须来自输入；
- 不重新读取视频；
- 不重新调用 V2.1a；
- 不修改 V2.1a；
- 不修改 V1。

### 11.2 最低测试要求

至少包含：

1. Schema 单测；
2. Primary Driver 唯一性测试；
3. `supporting_drivers <= 2`；
4. Evidence 必须来源于输入；
5. Intent Strength enum 校验；
6. 缺少 `creative_tags` 必要字段时 fail fast；
7. 10 条 Seed Benchmark Runner。

## 12. Done Definition

V2.1b 完成的标准是：

```text
V2.1a creative_tags.json
→ V2.1b
→ 唯一 Primary Driver
  + 真正的 Unresolved Question
  + Intent Strength
  + Supporting Drivers
  + 可追溯 Evidence
```

并且 Seed Benchmark 达到：

- Primary Driver Semantic Match >= 8/10；
- Unresolved Question Semantic Match >= 8/10；
- Primary Uniqueness = 10/10；
- Evidence Grounding = 10/10。

达到该标准后冻结 V2.1b，正式进入 **V2.2 Hero Strategy**。
