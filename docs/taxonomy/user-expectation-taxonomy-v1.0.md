# 用户期待 Taxonomy V1.0

> 状态：Canonical / Implementation Source
>
> 原始来源：`素材级标签文档（初稿）` → Sheet `用户期待（素材推理出来的）`
>
> 用途：V2.1a Creative Tagging 的 User Expectation Taxonomy。本文忠实转录原表的标签描述、主要识别信号、识别示例与排除/边界规则。
>
> 正式枚举：15 个用户期待标签（含 `无法判断（对于这种情况给一个候选）`）。

## 标签定义

| 创意诱发期待 | 标签描述 | 主要识别信号 | 识别示例 | 排除/边界规则 |
|---|---|---|---|---|
| 继续获得答案 | 用户期待悬念被揭晓，获得当前尚未说明的重要信息或答案。 | 秘密｜答案｜其实｜为什么｜别划走｜接下来告诉你 | 有一个很多人不知道的唱歌秘密…… | 脚本已明确承诺课程、权益或具体方法时，应选择更具体的期待标签。 |
| 规避风险/损失 | 用户期待了解错误行为的风险，并找到避免伤害、浪费或继续损失的方法。 | 小心｜长期错误｜后果｜再不改就晚了｜少走弯路 | 长期错误发声可能伤害嗓子，应该怎样避免？ | 只描述当前唱歌问题、不强调风险或损失时，标解决具体痛点。 |
| 解决具体痛点 | 用户期待解决片头明确指出的气息、高音、音准、音色、自信等具体问题。 | hook_pain_topics非空｜痛点场景｜共情提问｜生活质量 | 唱歌上气不接下气、高音上不去怎么办？ | 只讲方法但没有指向具体问题时，标掌握简单方法。 |
| 掌握简单方法 | 用户期待立即学到简单、可操作、可模仿的动作、练习或技巧。 | 实操教学｜简单动作｜跟着做｜示范｜带练 | 就这么一吸，身体通道就通了。 | 只解释专业原理、没有明确操作步骤时，标理解专业原理。 |
| 理解专业原理 | 用户期待理解唱歌问题背后的原理、机制或正确认知。 | 科普内容｜原理｜原因｜发声位置｜气息机制 | 唱歌不是只靠嗓子，而是需要打开身体通道。 | 开头已经进入动作示范或带练时，优先掌握简单方法。 |
| 获得/复制演唱效果 | 用户期待自己也能获得画面展示或脚本承诺的声音、技巧与表现改善。 | 效果呈现｜效果对比｜效果承诺｜唱得更好｜高音轻松 | 以前唱不上去的高音，现在也能轻松唱出来。 | 重点是跟随某位学员的经历和学习路径时，标复制学员成功路径。 |
| 复制学员成功路径 | 用户期待像其他学员一样，通过相似的学习过程获得改善。 | 用户故事｜学员背书｜成果背书｜学员见证｜从众引导 | 这个零基础学员跟着练习后，也能自信唱歌了。 | 只有教师自身演唱或一般效果展示时，标获得/复制演唱效果。 |
| 获得专业指导 | 用户期待由具备资历、经验或权威身份的老师提供可靠指导。 | 资历背书｜传承背书｜机构背书｜身份头衔｜从业经验 | 国家一级演员总结三十多年教学经验进行指导。 | 只有头衔展示但开头重点明显是权益、课程或CTA时，按主要信息判断。 |
| 获得课程权益 | 用户期待获得课程、赠品、价格优惠、限时资格或其他附加权益。 | 附加价值｜价格优惠｜稀缺课程｜稀缺预告｜赠送｜限时 | 这套四天身体唱歌课程现在可以免费领取。 | 只强调课程容易领取但没有具体权益时，标低门槛开始学习。 |
| 获得效果与保障 | 用户期待获得明确学习变化，同时相信服务、课程安排或学习过程有保障。 | 效果承诺｜服务承诺｜产品承诺｜反复观看｜全程陪伴 | 课程可以反复观看，跟着练习后声音会更稳定。 | 只有演唱结果画面、没有保障或承诺语境时，标获得/复制演唱效果。 |
| 了解系统课程 | 用户期待了解课程内容、课程结构，以及课程是否能系统解决自己的问题。 | 课程内容引导｜课表｜第几节课｜课程模块｜课程页面 | 想解决气息问题看第一节，想轻松唱高音看第三节。 | 只展示点击、报名或品牌尾帧时，标进入领取/报名流程。 |
| 低门槛开始学习 | 用户期待不受基础、时间、地点或复杂流程限制，可以轻松开始学习。 | 便利性｜领取流程｜零基础保障｜一部手机｜随时随地｜不用下载 | 没有基础也能学，一部手机在家就可以开始。 | 片头明确以赠品、优惠或稀缺资格为重点时，标获得课程权益。 |
| 进入领取/报名流程 | 用户期待立即点击、领取、报名或进入后续课程流程。 | 行动指令｜选择引导｜价值引导｜课程尾帧｜点击下方链接 | 点击视频下方链接，立即领取课程。 | CTA只是片段结尾附带表达，而主要信息是权威、方法或效果时，不应覆盖主要期待。 |
| 了解人物/故事结果 | 用户期待继续了解人物经历、学员事件、剧情冲突或故事结局。 | 剧情演绎｜人物传记｜原生花絮｜受访演讲 | 本该站在事业顶峰的他，却做了一个令人意外的决定。 | 故事主体是学员改善且已有明确学习证据时，标复制学员成功路径。 |
| 无法判断（对于这种情况给一个候选） | 片头脚本和画面不足以判断创意试图激发的主要用户期待。 | 脚本缺失｜无有效画面｜只有转场或装饰素材 | 无有效脚本和视觉信息。 | 存在明确方法、效果、痛点、权益或行动信息时不能使用。 |

## 实现约束

- 最终只输出一个正式 `user_expectation`。
- `排除/边界规则` 是 Taxonomy 的组成部分，不得只把标签名和示例提供给模型。
- Opening Type 与 User Expectation 必须分别判断，禁止机械映射。
- 当标签为 `无法判断（对于这种情况给一个候选）` 时，按 Spec 输出一个 candidate；存在明确方法、效果、痛点、权益或行动信息时不能使用该标签。
- 具体输出 Schema、Evidence 与 Confidence 规则以 `docs/v2.1a-creative-tagging-spec-v1.0.md` 为准。
