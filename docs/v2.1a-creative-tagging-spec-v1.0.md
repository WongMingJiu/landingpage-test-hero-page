# V2.1a Creative Tagging Spec V1.0

> 状态：Approved for implementation
>
> 所属阶段：V2.1 Creative Understanding / Phase 1
>
> 本文只定义 **V2.1a Creative Tagging**。不包含 Primary Driver、Hero Strategy、Hero Copy、生图或线上实验。

---

## 1. 目标

V2.1a 的目标不是“尽可能完整地描述广告”，而是：

> **基于广告点击决策窗口内的真实多模态信息，使用现有唱歌业务标签体系，为 V2.1b Intent Decision 提供少而可靠的结构化语义输入。**

当前版本由千人千面项目自行完成自动打标，不考虑未来素材中心是否会预先提供标签。

### 1.1 V2.1a 输出三类标签

1. **Value Tags**：素材实际表达了哪些业务价值，多标签；
2. **Opening Type**：片头综合策略，唯一标签；
3. **User Expectation**：素材主要诱发用户下一步期待什么，唯一标签。

### 1.2 非目标

V2.1a 不负责：

- 判断 Primary Driver；
- 写 Hero 标题/副标题；
- 设计 Hero；
- 生图；
- 判断整页模块排序；
- 判断所有素材是否值得个性化。

## 2. V1 / V2 隔离原则

V2.1a 必须作为独立能力建设，不改变 V1 当前行为。

原则上不修改：

```text
run.sh
analyze.py
generate.py
generate_image.py
assets/categories/singing/analyze_prompt.md
assets/categories/singing/generate_prompt.md
现有 V1 输出结构
```

V2.1a 的结果独立输出，例如：

```text
output/{video_name}/v2/creative_tags.json
```

不得覆盖 V1 的 `analysis.json` 或 `design_refer/`。

## 3. 业务 Taxonomy：只复用，不重新发明

V2.1a 使用现有《素材级标签文档（初稿）》中的三套业务 Taxonomy 作为唯一标签来源。

### 3.1 Value Taxonomy

来源：`唱歌补充价值标签(新-需拓展)`。

共 7 个一级类、36 个二级标签，当前均为 MVP 启用。

#### 演唱能力

- 稳定气息
- 改善音色与声音质感
- 增强声音稳定与力量
- 正确发声并保护嗓音
- 突破高音
- 突破低音
- 顺畅音域转换
- 改善音准并减少跑调破音
- 增强情感表达
- 掌握通用演唱能力

#### 心理障碍突破

- 敢于开口演唱
- 建立演唱自信
- 降低天赋与嗓音条件焦虑
- 降低年龄焦虑

#### 学习降阻

- 零基础可学
- 方法简单易操作
- 降低乐理与理解门槛
- 降低时间与地点限制
- 支持反复学习
- 获得辅导与答疑
- 获得系统学习路径

#### 专业认知提升

- 识别自身唱歌问题
- 纠正错误唱歌认知
- 理解发声原理
- 明确问题解决路径
- 获得演唱效果参照
- 获得可复制学习范例

#### 社交价值

- 获得他人认可
- 提升社交参与与自我表达

#### 信任保障

- 获得专业指导
- 获得效果与服务保障
- 减少试错与选择成本

#### 课程权益

- 获得课程与学习资源
- 便捷领取并快速开始
- 把握限时稀缺机会
- 明确学习入口

> 实现时必须保留原表中的“标签描述 + 识别示例”，不能只把标签名作为裸枚举塞给模型。

### 3.2 Opening Taxonomy

来源：`片头类型`。

正式枚举：

1. 强拦截口播型
2. 反常识/悬念型
3. 警示/数据冲击型
4. 痛点共鸣型
5. 教学演示型
6. 知识科普型
7. 演唱效果型
8. 效果对比型
9. 学员故事证明型
10. 权威背书型
11. 利益福利前置型
12. 承诺保障前置型
13. 课程内容导览型
14. 低门槛领取型
15. 行动引导型
16. 剧情/内容叙事型
17. 图文/课程展示型
18. 其他/无法判断

Opening Type 必须遵循原表的定义、脚本信号、分镜信号、默认优先级和识别规则。

### 3.3 User Expectation Taxonomy

来源：`用户期待（素材推理出来的）`。

正式枚举：

- 继续获得答案
- 规避风险/损失
- 解决具体痛点
- 掌握简单方法
- 理解专业原理
- 获得/复制演唱效果
- 复制学员成功路径
- 获得专业指导
- 获得课程权益
- 获得效果与保障
- 了解系统课程
- 低门槛开始学习
- 进入领取/报名流程
- 了解人物/故事结果
- 无法判断（对于这种情况给一个候选）

必须保留原表中的“主要识别信号 + 排除/边界规则”。这些边界规则是分类的一部分，不得丢弃。

## 4. 输入合同

V2.1a 必须是多模态任务。

### 4.1 必需输入

```text
video / sampled frames
transcript with timestamp
可获取的画面字幕/文字
Taxonomy definitions and boundary rules
```

### 4.2 可选输入

V1 `analysis.json` 可以作为辅助上下文，但不得成为标签判断的唯一依据，也不得直接复制其痛点/卖点排序作为答案。

### 4.3 核心原则

```text
Raw multimodal evidence > existing structured inference > model common-sense completion
```

素材没有表达的内容，不允许因为“这类课程通常会有”而补标签。

## 5. Decision Window

### 5.1 默认窗口

```text
0–30s = Primary Decision Window
```

V2.1a 理解的是**用户点击或流失前实际可能接触到的广告内容**，而不是编导完整看完 60–180 秒视频后的全文总结。

因此：

> **Click-intent fidelity > Full-video comprehension**

### 5.2 30 秒必须使用完整多模态信息

判断依据包含：

- 口播；
- 演唱；
- 画面字幕；
- 人物关系；
- 动作示范；
- 学员/老师身份；
- 场景；
- 前后效果或观众反应；
- 课程/权益视觉信息。

必须明确：

> `transcript_sparse != semantic_sparse`

ASR 缺失、没有口播、正在唱歌，都不能自动触发扩窗。如果画面本身已经足以判断，仍然使用 0–30s。

### 5.3 Semantic Sufficiency Check

30 秒结束时检查是否已有足够证据稳定判断：

1. Opening Type；
2. Active Value Tags；
3. User Expectation。

如果三者均可稳定判断：停止分析。

只有当**多模态语义本身仍不足**时，才允许：

```text
0–30s → extend to 0–60s
```

### 5.4 扩窗原则

30–60s 只能：

- 补充缺失语义；
- 解释前段演唱/视觉；
- 消除相邻标签歧义；
- 完成尚未闭环的命题。

不得因为后段信息“更完整、更强、更像销售文案”，推翻前 30 秒已经充分成立的判断。

> **Extension evidence may clarify, but must not seize control from a sufficiently supported primary-window intent.**

60 秒后默认不进入正常决策窗口。完整视频仅用于 Debug、Benchmark 复核或特殊人工 Review。

## 6. Value Tagging 规则

### 6.1 Matched Value Tags 与 Active Value Tags 同时保留

V2.1a 不能为了 Intent Decision 只保存 3–5 个标签。

需要区分：

#### `matched_value_tags`

所有在决策窗口内达到正式证据门槛的 Value Tags。

这是素材语义事实层。

#### `active_value_tags`

从 Matched Tags 中挑出真正会影响 V2.1b Intent Decision 的少量高显著性标签。

这是下游决策输入层。

### 6.2 Evidence Strength

每个 Matched Value Tag 必须标注：

```text
strong | medium
```

`weak` 证据不得进入正式 `matched_value_tags`。

#### Strong

- 素材直接表达该价值；并且
- 位于核心前段、被持续展开、重复、演示或案例强化。

#### Medium

- 素材明确表达该价值；
- 但只是辅助信息，不是内容主轴。

#### 不允许打标

- 仅由常识推测；
- 仅因课程领域相关；
- 从一个标签自动脑补多个潜在结果；
- 素材没有实际证据。

### 6.3 Salience

Active Tags 标记：

```text
primary | supporting
```

Primary Salience 主要参考：

1. 是否处于开场/前段核心位置；
2. 后续是否继续展开；
3. 是否有重复、字幕强调、动作、结果或案例强化；
4. 是否参与素材的核心因果链。

### 6.4 Active Tags 数量限制

全局：

```text
Primary Salience: 1–2
Supporting Salience: 0–3
Active Value Tags total <= 5
```

各一级类 Active 上限：

| 一级类 | Active 上限 |
|---|---:|
| 演唱能力 | 3 |
| 心理障碍突破 | 2 |
| 学习降阻 | 2 |
| 专业认知提升 | 2 |
| 社交价值 | 1 |
| 信任保障 | 1 |
| 课程权益 | 2 |

该限制只约束 Active Tags，不限制符合证据门槛的 Matched Tags。

### 6.5 Precision 优先

V2.1a 第一阶段优化目标：

> **Precision > Recall**

宁可漏掉一个边缘标签，也不要为了追求覆盖率把一条素材打成 10–20 个“都沾边”的标签。

## 7. Value Tag 关键边界规则

### 7.1 稳定气息 vs 正确发声并保护嗓音

- 断气、上气不接下气、气息不稳 → `稳定气息`
- 喉咙用力、声音卡喉、发声位置、伤嗓风险 → `正确发声并保护嗓音`

### 7.2 改善音色与声音质感 vs 增强声音稳定与力量

- 圆润、通透、悦耳、混响、大白嗓 → `改善音色与声音质感`
- 发虚、发抖、飘、穿透力、力量不足 → `增强声音稳定与力量`

### 7.3 突破高音 vs 顺畅音域转换

- 高音唱不上去 → `突破高音`
- 明确高中低音切换/真假声或音域转换 → `顺畅音域转换`

不能因为“高低音转换”中出现“高音”就默认两个都标为 Strong。

### 7.4 敢于开口演唱 vs 建立演唱自信

- 是否敢在人前唱、从不敢唱到开口 → `敢于开口演唱`
- 对自身歌声/学习能力的自我怀疑与信心 → `建立演唱自信`

### 7.5 零基础可学 vs 方法简单易操作 vs 降低乐理与理解门槛

- “没学过也可以” → `零基础可学`
- “几个简单动作/照着做” → `方法简单易操作`
- “不用复杂乐理/专业知识” → `降低乐理与理解门槛`

三个标签可同时存在，但必须分别有证据。

### 7.6 识别自身唱歌问题 vs 明确问题解决路径

- 列出气息、高音、大白嗓等问题 → `识别自身唱歌问题`
- 明确“问题 A → 课程/步骤 A” → `明确问题解决路径`

### 7.7 纠正错误唱歌认知 vs 理解发声原理

- “你原来以为 X，其实不是” → `纠正错误唱歌认知`
- 解释气息、身体通道、肌肉、发声位置等机制 → `理解发声原理`

### 7.8 获得演唱效果参照 vs 获得可复制学习范例

- 老师/普通人物直接展示唱得好、效果好 → `获得演唱效果参照`
- 明确存在学员身份、学习事实/路径、改善结果 → `获得可复制学习范例`

不能因为出现“学员”二字就自动判为可复制学习范例。

## 8. Opening Type 决策规则

Opening Type **只能输出一个综合类型**。

不输出 Primary + Secondary Opening。

### 8.1 识别单元

沿用原表规则：

> 第一有效脚本片段，以及与该脚本片段时间范围重叠的所有有效分镜。

模型应保留原始 script/visual signals 作为解释证据，但最终只输出一个 `opening_type`。

### 8.2 多分镜规则

1. 排除无有效画面、转场、装饰素材；
2. 优先选择与脚本策略语义匹配的分镜；
3. 再按重叠时长最长、开始时间最早决胜。

### 8.3 脚本多标签

把第一有效脚本片段中的策略信号映射到候选片头类型，按照原 Taxonomy 决策优先级输出一个综合类型，同时可以保留原始候选信号供 Debug。

### 8.4 分镜覆盖

分镜主要用于确认呈现形式和提高置信度。

只有类似“演唱前后对比”等强视觉证据，可以覆盖普通脚本类型。

### 8.5 Fallback

- 脚本缺失：用第一有效视觉分镜兜底，`source_mode=visual_only`；
- 画面缺失：按脚本判断，`source_mode=script_only`，confidence 最高只能 medium；
- 两者均不足：`其他/无法判断`，禁止根据课程知识库补猜。

### 8.6 决策优先级

沿用原表：

```text
1  强拦截口播型
2  效果对比型
3  教学演示型
4  演唱效果型
5  反常识/悬念型
6  警示/数据冲击型
7  痛点共鸣型
8  知识科普型
9  学员故事证明型
10 权威背书型
11 利益福利前置型
12 承诺保障前置型
13 课程内容导览型
14 低门槛领取型
15 行动引导型
16 剧情/内容叙事型
90 图文/课程展示型
99 其他/无法判断
```

注意：优先级用于**同一有效开头单元内存在多个候选策略**时决胜，不是允许后段信息覆盖前段主权。

## 9. User Expectation 决策规则

User Expectation 只输出一个正式标签。

不输出 Primary + Secondary Expectation。

只有证据不足时，允许：

```json
{
  "label": "无法判断（对于这种情况给一个候选）",
  "candidate": "掌握简单方法"
}
```

### 9.1 关键边界

- 已明确具体痛点 → `解决具体痛点`
- 有动作、跟着做、带练 → `掌握简单方法`
- 只讲原因/机制/正确认知，没有明确操作 → `理解专业原理`
- 一般演唱/结果展示 → `获得/复制演唱效果`
- 学员身份 + 学习事实/路径 + 结果 → `复制学员成功路径`
- 免费、赠送、稀缺资格是主体 → `获得课程权益`
- 无特殊权益，重点是零基础/手机/方便开始 → `低门槛开始学习`
- CTA 只是结尾附带 → 不得覆盖前面的主要期待
- 课程模块/第几节解决什么问题 → `了解系统课程`

Opening Type 与 User Expectation 必须分别判断。

禁止：

```text
Opening = 演唱效果型
=> 自动 Expectation = 获得/复制演唱效果
```

同一种 Opening 可以产生不同 Expectation。

## 10. Evidence 规范

所有正式标签必须可追溯。

Value Tag 示例：

```json
{
  "category": "专业认知提升",
  "label": "纠正错误唱歌认知",
  "evidence_strength": "strong",
  "salience": "primary",
  "evidence": [
    {
      "time": "00:00-00:07",
      "source": "subtitle|audio|visual|transcript",
      "content": "不是用嗓子挤出来的声音"
    }
  ]
}
```

Opening / Expectation 也必须包含至少一条直接 evidence。

### 10.1 Confidence

第一版使用：

```text
high | medium | low
```

不用不可校准的 `0.87 / 0.93` 等伪精确数字。

## 12. Semantic Sufficiency / Failure Handling

当 0–30 秒内无法稳定判断三类输出时：

```text
semantic_sufficiency = insufficient
extended = true
used_seconds = 60
```

60 秒仍不足：

```json
{
  "review": {
    "needed": true,
    "reason": "insufficient_multimodal_evidence"
  }
}
```

禁止为了保证 JSON 有值而强行猜测。

## 13. Benchmark 与验收

首轮使用 `docs/benchmarks/singing-creative-tagging-benchmark-v1.0.md` 中的 10 条真实唱歌素材作为 Seed Benchmark。

### 13.1 Schema

- 10/10 JSON 可解析；
- 必填字段完整；
- 所有标签必须来自现有 Taxonomy。

### 13.2 Value Tagging

重点评估三类错误：

1. **错标**：素材没有表达却输出；
2. **过标**：勉强成立但不重要的标签大量进入 Active；
3. **漏标**：真正影响承接决策的核心标签未识别。

首轮目标强调 Precision 与 Active Tag 可用性，不追求 36 标签全集 Recall。

### 13.3 Opening Type

目标：

> 10 条中至少 9 条与人工 Ground Truth 一致；边界样本允许 Benchmark 明确记录 `acceptable_alternative`。

### 13.4 User Expectation

目标：

> 至少 9/10 与人工 Ground Truth 一致。

### 13.5 Decision Window

模型不得因为 ASR 稀疏自动扩展到 60 秒。

在 Seed Benchmark 中，真实视觉信息加入后，10 条样本的 0–30 秒均已具有足够多模态语义，因此正常结果应为：

```text
used_seconds = 30
extended = false
```

### 13.6 稳定性

同一素材重复运行 3 次：

- Opening Type 不应漂移；
- User Expectation 不应漂移；
- Active Value Tags 核心标签应保持高度稳定。

## 15. 实现原则摘要

```text
现有业务 Taxonomy，不重造
        ↓
0–30s 多模态 Decision Window
        ↓
Semantic Sufficiency
        ↓
Matched Value Tags
        ↓
Active Value Tags（<=5）
        ↓
唯一 Opening Type
        ↓
唯一 User Expectation
        ↓
Evidence-backed creative_tags.json
```

核心原则：

> **Creative Tagging 不是把视频里所有“沾边的信息”标签化，而是忠实保留有证据的业务语义，并额外筛出足以影响后续页面承接决策的高显著性标签。**
